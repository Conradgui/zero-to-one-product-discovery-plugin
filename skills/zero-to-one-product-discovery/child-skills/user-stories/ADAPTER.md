# User Stories

## Role

Produce user stories, story-map slices, or a story readiness review from grounded MVP and requirement context.

## Required Input

- MVP slice.
- User / scenario / job.
- Confirmed requirement or PRD section.
- Scope boundaries and non-goals.
- Risks and unresolved questions.
- Expected output mode.

## Output Contract

- User stories grouped by journey, release slice, or requirement.
- Acceptance-criteria needs called out separately.
- Deferred ideas labeled as deferred.
- Assumptions and unknowns.
- The highest-leverage blocking question for the current turn if scope is not grounded.
- Readiness signal.
- Context Resume Packet.

## Boundaries

- Do not generate a full backlog before MVP scope is grounded.
- Do not treat deferred stories as committed work.
- Do not choose release sequencing beyond the requested output mode.
- Do not ask multiple questions in one turn; return the next blocker and let the main workflow loop after the user answers.
