# Design Reference Protocol

Use this reference only during UI/UX, website, brand, visual system, interaction prototype, or product presentation stages.

Do not let visual references influence early problem framing, MVP selection, or technical feasibility unless visual quality is itself the core product risk.

## Inputs

- `design_reference_urls`
- `design_reference_goal`
- `visual_quality_bar`
- `interaction_quality_bar`

## Rules

- Explain why each reference matters for the current project.
- Separate transferable principles from content that should not be copied.
- Analyze structure, hierarchy, interaction, motion, narrative, and conversion logic.
- Do not copy proprietary assets, visual compositions, text, brand elements, or unique interaction signatures.
- If live web analysis is needed, use current verifiable sources and state the access date.

## Analysis Dimensions

| Dimension | Questions |
|---|---|
| Information architecture | How is content grouped, sequenced, and prioritized? |
| First viewport | What is communicated before scrolling? |
| Visual hierarchy | How does the page direct attention? |
| Interaction path | What actions are encouraged, delayed, or reduced? |
| Motion rhythm | Does motion clarify state or create spectacle? |
| Brand expression | What tone and product promise are implied? |
| Conversion path | How does the design move users toward a decision? |
| Transferable principle | What can be adapted without copying? |
| Non-transferable element | What should not be reused? |

## Output

1. Reference purpose.
2. Reference analysis table.
3. Transferable principles.
4. Non-transferable elements.
5. Current project design implications.
6. Mermaid information architecture or interaction flow.
7. Design trade-off table.
8. Decision Log entries needed.
9. Context Resume Packet.
